# Hotel HIIT

出張中に HIIT をやったかどうかを、ワンタップで残すだけのアプリです。
iPhone のホーム画面から開いて、大きなボタンを押す。それだけ。

- **入力** — ボタン1つ。押したら実施済み、もう一度押せば取り消し
- **あとから直す** — ヒートマップのセルを押せば、その日の記録を入れたり消したりできる
- **可視化** — 連続日数・最長連続・直近30日の実施数と、直近12週のヒートマップ
- **保存先** — この端末の `localStorage` だけ。サーバーもアカウントもない
- **オフライン** — Service Worker がアセットをキャッシュするので、機内でも起動する

ビルド工程はありません。HTML と CSS と JavaScript が1枚ずつあるだけです。

## iPhone で使う

公開した URL を Safari で開き、共有ボタンから **ホーム画面に追加** を選びます。
以降はアイコンから起動し、アドレスバーのない単体アプリとして動きます。

> ホーム画面に追加した状態で使うこと。Safari のタブのまま放置すると、
> 7日間使わなかった時点でブラウザ側のストレージが破棄される場合があります。
> ホーム画面に追加した PWA はこの対象外ですが、それでも「データ」から
> ときどき JSON を書き出しておくのが安全です。

起動できたら、**データ** を開いて `オフライン起動: 有効` と出ているか一度だけ確認してください。
`無効` の場合は Service Worker が登録できていないので、電波のない場所では起動しません。

## 公開する（GitHub Pages）

静的ファイルだけなので、リポジトリをそのまま配信できます。

```bash
gh repo create hotel-hiit --private --source=. --push
```

そのうえで GitHub の Settings > Pages で Source を `main` ブランチのルートに設定します。
`https://<ユーザー名>.github.io/hotel-hiit/` で開けるようになります。

> Private リポジトリで Pages を使うには有料プランが必要です。
> 無料プランなら `--public` にしてください。記録は端末内にしか無いので、
> 公開されるのはコードだけです。

## ローカルで動かす

```bash
python3 -m http.server 4173
```

`http://localhost:4173/` を開きます。`file://` で直接開くと Service Worker が
登録できないので、必ず HTTP で配信してください。

## データの持ち運び

**データ** セクションから JSON で書き出し・読み込みができます。
読み込みは既存の記録とマージされ、同じ日付が二重に増えることはありません。

```json
{
  "version": 1,
  "exportedAt": "2026-09-14T13:00:00.000Z",
  "days": { "2026-09-14": "2026-09-14T13:00:00.000Z" }
}
```

`days` のキーがローカル日付、値は記録した時刻です。キーが存在すれば実施済みという扱いです。

## 色について

ヒートマップは二値（やった / やっていない）なので、実施を sequential blue の濃いステップ、
未実施をニュートラルなグリッド色に割り当てています。ライトとダークで別のステップを選び、
どちらの背景でもコントラストが出るようにしています。値は `styles.css` の先頭にまとまっています。

## watchos-draft/

Apple Watch 単体アプリとして作りかけた SwiftUI の雛形です。今は使っていません。

Watch から直接押したくなったらここから再開できますが、Xcode（10GB 超）が必要で、
無料の Apple ID で入れた開発ビルドは **7日で署名が切れて起動しなくなります**。
出張中に使うものとしては向かないので、Web 版を本線にしています。
